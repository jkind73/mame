# SCU DSP source-note audit — 2026-10-10

The assigned SCU DSP source-note audit is implemented and software verified. The existing broad item and its section-12.4 DSP entry are marked complete; only those two checklist markers changed. No physical-hardware timing validation is claimed.

The Sega reference is the local SCU manual, `segahtml/hard/scu_/hon/p03_03.htm` (control port), `p04_01.htm` (register widths and bus clocks), `p04_03.htm` (prefetched branch instruction and END/DMA independence), and `p04_51.htm`–`p04_59.htm` (instructions). No physical Saturn was used. Instruction execution remains one DSP clock per instruction; DMA bus acknowledgements use the previously audited SCU wait model. Absolute hardware timing is not validated.

Confirmed fixes:

* LPS now repeats the prefetched following instruction directly. The old implementation reexecuted LPS between iterations, doubling the per-repetition instruction-clock cost. Its repeat state is saved, and a host PC load discards the old instruction pipeline. The fixture checks three repeated writes in four total instruction clocks.
* A prefetched branch instruction at address zero was lost because zero also indicated no pending delay. A separately saved pending flag now preserves that instruction for JMP, MVI PC, LPS and BTM, including address wraparound.
* EX stop/END no longer assert the device reset input. Previously, restarting EX released reset and canceled an unfinished independent DMA. A real-device regression fails before this fix and passes after it on both CPU cores, including debugger-enabled runs. Instruction execution now explicitly stops on EX=0 while DMA remains driven by its timer.
* The debugger hook now receives the address actually executed, including a pending delay slot, and is called after the DMA-resource conflict check. The separately saved CURPC debugger state also reports the executed address instead of the branch target. Waiting for DMA no longer reports an instruction that has not executed. The disassembler now returns SUPPORTED and conditional branch delay metadata.
* EP/PR writes have no effect while EX is zero, as the manual specifies. The former implementation could pause a stopped DSP and inhibit a later EX start.
* LOP writes are masked to the documented 12 bits. The four six-bit CT registers are now an array, saved together with unchanged debugger register names.
* Parallel X/Y reads formerly advanced CT before the D1 read. D1 could read the next RAM word, and a shared postincrement could happen twice. Reads now retain the instruction's original CT address, with one final increment per bank and explicit CT writes taking precedence. The real-method fixture reproduced the old discrepancy before this fix.

## Subsequent freeze and DMA-address fixes

The scheduler freeze was reproduced independently with an FRT compare interrupt whose handler deliberately leaves its request asserted and executes RTE. The DRC's accepted-interrupt path jumped to the handler before accounting for accumulated instruction cycles or checking exhaustion. Repeated RTE/interrupt entry never returned to the scheduler, and temporary instrumentation recorded cycle counts below -900 million. That path now accounts for its sequence and yields at the handler entry when exhausted. The original build times out in `sh7604_interrupt_yield_test.py`; the corrected DRC and interpreter pass. Logs: `/private/tmp/sh7604-interrupt-yield-before-20261010/` and `/private/tmp/sh7604-interrupt-yield-after-20261010/`. Temporary core tracing was removed.

Fixing the scheduler alone exposed the continuing game corruption: the slave entered the geometry copy at `060747AC` from `0604D808` with R6=0 and R7=0, after eight calls with valid destinations/counts. Its do-while loop wrapped the count and eventually reached an invalid CD data-port access. The incorrect descriptor was a consequence of DSP output DMA address stepping: Work RAM-H writes advanced twice per longword, as though both halfword callbacks were separate 16-bit-bus beats. MiSTer's `SCU.sv` `DMA_WA_NEW` advances once per C-bus longword; Mednafen 1.32.1's hardware-derived implementation independently does the same. The corrected engine increments once for the external 32-bit write, while preserving two increments for B-bus halfwords. No game-specific address correction, counter bypass or warning suppression is used.

## Completion follow-through

The follow-through audit found additional control defects beyond the game regression. Full-width EP/PR writes were falling through to EX and stopping the DSP, whereas Sega's control commands and both independent implementations preserve execution state for pause/resume commands. EP/PR now take precedence over EX/ES; stopped EP/PR remain ignored. ES eligibility uses the execution state before the write, so a stop+ES write cannot execute an extra instruction from a previously running program. The next ES write while stopped still executes one instruction.

The control port also reported `m_pc + 1` even though execution had already advanced the PC. It now returns the actual PC: END reports the following address, including FF-to-00 wraparound. Read-back masks expose only T0/S/Z/C/V/E/EX and the PC, excluding reserved and write-only command bits. Existing read-to-clear E/V behavior and side-effect-free debugger inspection are retained. The scheduler's maximum instruction cost is now one DSP clock, matching every instruction implementation; DMA bus acknowledgements remain asynchronous.

The instruction timing model uses master/4 for the DSP and one clock per instruction, including parallel moves, branches and loop repetitions. This agrees with Sega's approximately 14 MHz internal buses and Mednafen's two SH-2-clock instruction accounting. PAL/DOTSEL changes already propagate through the SCU clock-change callback. DMA keeps the audited startup/request, bus-owner waits, beat costs and final-acknowledgement scheduling. The four-DSP-clock initial request delay and absolute bus timings remain model values without physical-hardware validation; this audit does not manufacture a hardware measurement.

The updated actual-method tests pass ASan/UBSan. Temporary source copies restoring the old pause, ES and PC-read behavior each fail the new regressions independently; results are in `/private/tmp/scudsp-control-before-regressions-20261010/`. The final macOS SDL3 build succeeds.
